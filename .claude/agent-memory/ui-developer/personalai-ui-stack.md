PersonalAI SPA lives at `apps/ui` — React 19 + Vite 6 + TypeScript + Vitest 4 + Playwright. pnpm workspace; CI in `.github/workflows/ci.yml` (`js` job + `ui-e2e` job).

**Tooling weaknesses (durable, verify before relying):**
- No ESLint. `package.json` `lint` script is just `tsc --noEmit` (alias of `typecheck`). So CI `js` job runs tsc twice; no react-hooks / no-floating-promises linting.
- No coverage tooling installed and no coverage threshold/gate anywhere. `@vitest/coverage-*` is absent.
- Playwright runs Desktop Chrome only (`playwright.config.ts`) — no mobile/responsive viewport project.

**Auth model (post #217 cookie/CSRF migration):** `app_mode` local (zero-login dev) vs hosted (cookie login + double-submit CSRF). `api.ts` `authHeaders()` sends bearer token (if any) + `X-CSRF-Token` read from `pai_csrf` cookie; all calls send `credentials:"include"`. Backend resolves cookie-first then bearer. `App.tsx` gates: session loading -> Login on clean 401 -> render-app on error. XSS posture is strong: `Markdown.tsx` has no dangerouslySetInnerHTML and no rehype-raw, pinned by tests.

**Why this matters / how to apply:** When asked to add frontend tests or harden CI, propose adding ESLint + vitest coverage gate (they still don't exist as of the Pre-M8 Hardening sprint, verified 2026-06-12). The cookie/CSRF transport is still NOT exercised by any test (Login render IS tested now via Login.test.tsx + App.test.tsx 401->Login; but no test asserts `X-CSRF-Token`/`credentials:"include"` are sent, and logout->401 re-gate is untested) — recommend `api.test.ts` asserting credentials+CSRF headers before hosted deploy.

- C1 SSE parser FIXED + tested: `streamChat` in `api.ts` now guards `JSON.parse` (skips malformed frames) and flushes the trailing frame after the read loop (`buffer += decoder.decode(); processFrame(buffer)`). This was the "no answer" root cause. `api.test.ts` covers deltas/error/malformed/final-frame.
- A6 (#229) TraceItem FIXED + tested: union extended with `plan|critique|verification` plus `role`+`verdict` fields; `MessageDetails.tsx` renders them and has a GENERIC FALLBACK (`details-other`) for unknown future kinds. Tested in `MessageDetails.test.tsx`.
- A4 (#227) unified SSE wire format: parser reads only `delta`/`thinking` and ignores `done`/`finish_reason` — no UI assumption on per-chunk done. NOTE: `e2e/chat.spec.ts` CHAT_SSE fixture is STALE (still old per-chunk `done`/`finish_reason` format) — harmless but should be updated.
- Verdict given: GO for local M8; go-with-fixes for hosted.

**Side panel = unified Activity timeline (#374):** `SidePanel.tsx` renders `ActivityTimeline.tsx` as its centerpiece — one collapsible group per Q/A turn, newest on top, each turn's spine listing context+tools+reasoning in chronological order. It REUSES `ToolIO` (call+result pairing, egress allow-on-deny), `ContextComposition` (`collapsible={false}`), and the agent color code (`agentColors.ts` + violet tool / green ok / red err / #4a90d9 context accent). To avoid double-rendering the live context composition, `ContextMeter` is now called with `context={null}` (window-usage + chat-totals only). Per-turn timestamps come from `ChatMessage.created_at` (ISO; absent on the in-flight turn -> "just now"/live). A blocked tool now surfaces an Allow button in BOTH the transcript Details and the timeline, so egress-allow tests must use `getAllByTestId`, not `getByTestId`. Filter chips (All/Tools/Reasoning/Context) hide non-matching nodes; a turn with no visible nodes is hidden.

**Empty-doc / scanned-PDF state (#446, added 2026-06-25):** `DocumentChips.tsx` `DocumentStatus` now includes `"empty"` (exported `EMPTY_DOC_EXPLANATION` const). A doc whose `extractDocument` text is whitespace-only is marked `empty` in `Chat.tsx` `onDocumentFiles` (NOT an error — pypdf doesn't OCR scanned/image-only PDFs). The `empty` chip shows "no text found", opens a panel with the explanation (`document-empty-explanation` testid, no Copy), and is auto-excluded from folding/RAG because `smallDocs`/`largeDocs`/`doneDocs` filters only match small/large. An empty-only attachment can't be sent (Send checks `smallDocs.length`). Tests: `DocumentChips.test.tsx` (new), `Chat.test.tsx` empty-doc test, `e2e/attachments.spec.ts`.

**Chip panels open on HOVER (e2e gotcha):** composer + transcript chips (`DocumentChips`/`AudioChips`/`ImageChips`) open their hover panel on `onMouseEnter`; the chip's `onClick` TOGGLES. In Playwright, `.click()` first hovers (opens) then clicks (closes) -> panel gone. Use `.hover()` to open a chip panel in e2e, not `.click()`.

**editResubmit deferred-send doesn't fire under Playwright preview (verified 2026-06-25):** `Chat.tsx` `editResubmit` truncates+reloads then `setTimeout(() => sendRef.current(), 0)` to re-run. The truncate fires reliably but the deferred POST /chat re-run does NOT reproduce in the production preview build under Playwright (works under Vitest `act()`). So e2e for Edit asserts only the truncate effect (later turn discarded, `from_message_id` correct); the re-run depth is covered by the `Chat.test.tsx` unit test (asserts `streamChat` called with edited text). Don't assert the re-run POST in e2e.

**Vitest TS gotcha — capturing a callback/resolver in a test (verified 2026-06-26):** `let x: ((...)=>void) | null = null` assigned ONLY inside a callback (e.g. `vi.spyOn(...).mockImplementation(async (_id, cb) => { x = cb })` or a `new Promise((_,r)=>{x=r})`) makes this repo's tsc narrow `x` to `never` at the later `x?.(...)` call site -> `error TS2349: not callable`. Fix: use an object holder `const h: { fn?: T } = {}; ... h.fn = cb; ... h.fn?.(...)`. Property access doesn't suffer the closure-narrowing. Used in `FolderSourceCard.test.tsx` (SSE onProgress + deferred pauseFolder reject).

**Folder sources v2 (#458, added 2026-06-26):** Settings > Documents now has TWO labelled regions in `DocumentsPanel.tsx` — `individual-uploads` (the existing per-file upload, unchanged) + `<FolderSourcesPanel>`. `DocumentsPanel` now takes `token` (threaded from `SettingsView`). Folder state is NOT lifted into Chat.tsx — `FolderSourcesPanel` self-fetches via the `useFolderSources(token)` hook (mirrors Memory/Tools/McpPanel), keeping SettingsView thin. `api.ts` folder fns take `token` first (codebase convention) even though the #458 brief wrote `registerFolder(path,label)`. `registerFolder`/`resyncFolder` return discriminated `{ok}|{ok:false,error:{code,message}}` (never throw on structured backend errors, so the form/card show them inline). `streamFolderEvents(id,onProgress,token,signal)` reuses the module-private `pumpSSE`; it's best-effort (swallows abort/transport errors so a card keeps last-known counts). `FolderSourceCard` opens the SSE stream while mounted (effect dep `[folder.id, token]`), holds local status/counts (synced from props on object change), and pause/resume are optimistic-with-revert. The Remove dialog gets the card's LIVE counts (`{...folder, status, counts}`) so the purge total is current. Color rule: status pill is word+color (Idle green / Scanning amber / Error red / Paused muted); rollup shows only non-zero buckets with per-bucket hue, `aria-live="polite"`.

**Folder sources v2 — pass 2 drill-down (#458, added 2026-06-26):** A watched folder is a nested directory TREE (`folder_files.rel_path` is a POSIX path that can be nested). `api.ts` adds `FolderFileOut`/`FolderFileStatus`/`FolderDetail` + `fetchFolderDetail(token,id,{status?,after?,limit?})` (keyset on `rel_path`, limit<=200; `total` read defensively from `total`/`total_files`/`file_count`). New files: `folderUi.tsx` (shared color consts + `FILE_STATUS` map + `formatBytes`/`formatWhen` + `<FileStatusPill>`/`<StatusRollup>`), `FolderFileTree.tsx` (exports PURE `buildFileTree`/`dirCounts` for tests + collapsible tree UI; dirs before files, per-dir descendant rollup, `expandAll` prop auto-opens every dir when a filter/search is active), `FolderDetail.tsx` (Files/Entities tabs; Entities = P3 placeholder). `FolderSourceCard` got a `folder-expand-toggle` caret that lazy-mounts `FolderDetail` on first expand and passes its live SSE `counts` as `liveCounts` for the header. Key design choice: the status filter (All/Indexing/Errors/Stale/Synced) + debounced name search narrow LOADED files CLIENT-SIDE (compose without round-trips); "Load more" fetches raw keyset pages (`after`=last rel_path) — the server `status=` param exists but isn't used for the interactive filter. Filter defaults to Errors when any loaded file errored. Backend stores NO per-stage pipeline meta per folder-file — show only status/size/document_id/indexed_at/error_code+detail, no fake model/ms. The document affordance is a copy-id button (no global doc route exists). E2E in `e2e/folders.spec.ts` mocks `GET /folders/{id}` with nested rel_paths + one error file.

**Entity browser — pass 3 NER/KAG (#451, branch `feat/451-ner-kag` off the P2 branch, added 2026-06-26):** Entities are corpus-GLOBAL (one entity spans many docs/folders), so the browser is a THIRD top-level `DocumentsPanel` region ("Entities"/"Knowledge graph"), NOT per-folder. `api.ts` adds `Entity`/`EntityType`(person|org|location|date|product|event|other)/`EntityEdge`/`EntityDetail` + `fetchEntities(token,{type?,q?,limit?})` + `fetchEntityDetail(token,id)`. New `EntityBrowser.tsx`: groups entities by type (fixed TYPE_ORDER), type-filter chips + debounced name search are SERVER-DRIVEN here (re-fetch on type/q change — differs from FolderDetail's client-side narrowing, because the corpus can be large and `q` is a backend fuzzy search). Clicking an entity inline-expands its detail (aria-expanded button + `role=region` panel): source documents as copy-id buttons + graph edges rendered "relation -> dst" where the dst is a button that navigates to that entity. Entity category hue = fuchsia `#a21caf` (NER, reused from `RetrievalIO.tsx`/`ActivityTimeline.tsx`). Empty states differ: corpus-empty ("extracted as documents are indexed") vs filtered-empty ("No entities match"). `FolderDetail` Entities tab is now a one-line pointer to this global section (`folder-entities-empty` text contains "corpus-global"), NOT a per-folder duplicate. Tests: `EntityBrowser.test.tsx`, `e2e/entities.spec.ts` (register the `**/api/v1/entities/*` detail route AFTER the `**/api/v1/entities**` list route so detail wins for `/entities/{id}`).

**pnpm-only install gotcha (verified 2026-06-27):** the repo is a pnpm workspace (`packageManager: pnpm@11.5.1`). Running `npm install`/`npm install <dep>` from `apps/ui` FAILS with `sh: rrun: command not found` (gpt-tokenizer's postinstall `prepare` script runs under npm but not pnpm). Always add deps with `pnpm --filter @personalai/ui add <dep>`. tests/lint still run via `npx vitest run` / `npm run lint` (lint===tsc) fine — only dependency install must go through pnpm.

**Knowledge section + graph (added 2026-06-27, branch `feat/knowledge-section`):** New Settings section `knowledge` ("Knowledge", between Memory and Network in `SettingsView.tsx`). `KnowledgePanel.tsx` = Graph/Corpus tabs (role=tablist). Graph tab (`KnowledgeGraph.tsx`) reuses `EntityBrowser` as picker+accessible-alt (added optional `onFocusEntity`/`focusedId` props + per-chip `entity-open-in-graph` affordance — existing inline-expand behavior in Documents>Entities unchanged) and renders a focus+context ego-graph via **react-force-graph-2d** (new dep `^1.29.1`). Canvas is `aria-hidden`; the `graph-detail` rail (documents + co-occurring entities, both keyboard buttons) is the accessible path. New api.ts fns: `fetchEntityNeighborhood(token,id,cap=200)` (`/entities/{id}/neighborhood`) + `fetchDocumentEntities(token,id)` (`/documents/{id}/entities`). Shared palette/type-meta in `knowledgeUi.tsx` (entity hues + one-letter `TypeBadge` + `GraphLegend`; docs = slate square — shape not color distinguishes node classes). Corpus tab (`KnowledgeCorpus.tsx`, P0 overview only) = stat cards + per-doc table with amber "Not indexed" when chunk_count==0. **Test gotcha:** MUST `vi.mock("react-force-graph-2d", () => ({ default: ... }))` in any test that mounts the graph (jsdom has no canvas); capture `props.graphData` in the mock to assert derived nodes/links. P1 (Retrieval Explorer + chunk inspector) skipped — standalone `/retrieve` + `/chunks` endpoints don't exist yet. **Perf follow-up:** react-force-graph-2d lands in the main bundle (build warns >500kB; index chunk ~743kB) — consider `React.lazy` for the graph tab.
